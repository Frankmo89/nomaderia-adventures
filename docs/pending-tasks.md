## Completado

- [2026-07-05] **SectionDivider — textura de grano sutil (Fase 4, cierre final).** Basado en investigación de patrones Mobbin (Browserbase eleva un divisor de montaña plano solo con una capa de textura halftone/dither, no con geometría): se añadió un `<filter>` SVG compartido (`feTurbulence` → `feColorMatrix` → `feComponentTransfer` → `feComposite operator="in"`) que reduce ruido fractal a un speckle negro de alpha extremadamente bajo (~2-4.5%, vía `feFuncA slope="0.045"`). El `feComposite in="grain" in2="SourceGraphic" operator="in"` clippea el grano exactamente a la silueta del elemento que lo porta, evitando el bleed que forzó a retirar el `feGaussianBlur` anterior (ver entrada Phase 4a). **Edge Function `ingest-campgrounds` — rellena tabla `campgrounds` desde NPS API**
- Nueva función `supabase/functions/ingest-campgrounds/index.ts`. Llama a `GET /api/v1/campgrounds?parkCode={code}` de NPS (con paginación `limit/start`) para cada destino con `park_code IS NOT NULL`. Usa el mismo `NPS_API_KEY`, `requireAdmin`, `corsHeaders` y cliente service-role que `ingest-park-permits`. Parámetros: `{ force?, limit? (default 5, max 50), park_code? }`. Lógica de match por destino: busca fila existente en `campgrounds` por `nps_code` primero; si no hay, por `nombre` (case-insensitive, ILIKE sin wildcards); si hay → UPDATE; si no hay → INSERT con `nombre + destination_id`. Itera `destinations WHERE park_code IS NOT NULL` con los mismos filtros de `force`/`is_published`/`park_code` que `ingest-park-permits`.
- **Mapeo NPS → columna `campgrounds`** (solo estas columnas son escritas/actualizadas):
  - `nps_code` ← `campground.id`
  - `latitude` ← `latitude` (fallback: parse `lat:` del campo `latLong`)
  - `longitude` ← `longitude` (fallback: parse `long:` del campo `latLong`)
  - `direccion` ← `addresses[]` tipo "Physical": `"${line1}, ${city}, ${stateCode} ${postalCode}"`
  - `num_sitios` ← `campsites.totalSites` (fallback: `numberOfSitesReservable + numberOfSitesFirstComeFirstServe`)
  - `precio_usd` ← `fees[]`: primer fee estándar por noche (excluye Group/Senior/Access en título); `null` si ninguno parseable
  - `reservable` ← `numberOfSitesReservable > 0`
  - `reserva_url` ← `reservationUrl`
  - `tiene_agua` ← `amenities.potableWater[]`: algún valor distinto de "No" → `true`, si no `false`
  - `banos` ← `amenities.toilets[]`: contiene "Flush" → `'con descarga'`; contiene "Vault" o "Pit" → `'pozo'`; si no → `'ninguno'`
  - `rv_max_pies` ← `accessibility.rvMaxLength` (número > 0; si es 0 o null → `null`)
  - `senal_celular` ← `amenities.cellPhoneReception`: `"No"` exacto → `'Sin señal'`; contiene "Yes" → `'Hay señal'`; cualquier otro → `null`
  - `amenidades` ← jsonb con 8 claves en español: `{ agua_potable, banos, internet, recoleccion_basura, casilleros_comida, tienda, estacion_vaciado_rv, anfiteatro }`
- **Columnas curadas que NUNCA toca esta función** (en UPDATE ni en INSERT): `nota_soul`, `es_recomendado`, `orden`, `accesibilidad_nota`, `dentro_del_parque`, `precio_nota`, `estado`, `elevacion_ft`, `horario`. En INSERT también se omiten (quedan `null`/default para curation humana). `nombre` se escribe solo en INSERT.
- Retorna `{ ok, procesados, campamentos_insertados, campamentos_actualizados, restantes, detalle: [{ park_code, status, inserted, updated, reason? }] }`.
